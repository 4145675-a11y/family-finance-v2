# BROWSER-TESTS — בדיקות דפדפן אמיתיות

> אבן דרך B1. משלים את `docs/CI-GATES.md` (שער 14, `E2E`) ואת `docs/COMMANDS.md`.

## 1. למה זה קיים

יחידה מוכיחה שפקודה נכונה. היא אינה מוכיחה שאדם שלוחץ על כפתור מגיע אליה.

שלושת הדברים שרק דפדפן יכול להוכיח:

1. **לחיצה על "אישור" כותבת רשומה אחת** — ושנייה, אחרי תגובה שאבדה, אינה כותבת שנייה.
2. **המסך והמסמך מסכימים** — היתרה בראש כרטיס המלווה והטור בהיסטוריה שמתחתיו
   הם אותו חשבון (`M1`).
3. **אפשר למצוא את הדברים** — בלי לדעת כתובות, ובלי לגלול לצדדים בטלפון.

## 2. שתי חבילות, ולמה

| | `npm run e2e` | `npm run e2e:live` |
|---|---|---|
| backend | `local_json` בתיקייה זמנית | המסד האמיתי |
| סודות | **אין** | `SUPABASE_DB_URL` |
| רץ ב־CI | **כן** | לא |
| מכסה | כל המסלולים הכספיים | כניסה, RLS, בידוד |
| פורט | 3141 | 3142 |

**למה החבילה המקומית אינה "פחות אמיתית"**: `local_json` הוא backend מן המניין של
המוצר (`ADR-0024`, `ADR-0031`). הוא מריץ **אותן פקודות ואותם server actions** כמו
הפריסה המתארחת, וכל כתיבה בו נגמרת במסמך JSON על הדיסק. הבדיקות קוראות את המסמך
הזה ומונות — לא את המסך.

מה שהוא באמת לא מכסה: Supabase Auth, row-level security ו־PostgREST. לשלושתם יש
`e2e:live`, ובנוסף `npm run integration` ו־`npm run validate:production-path`.

## 3. בידוד — איך זה בטוח להריץ על המכונה שיש בה משק בית אמיתי

### החבילה המקומית

- **תיקייה זמנית**: `globalSetup` יוצר `mkdtemp`, בונה בה משק בית דרך **הפקודות
  של המוצר עצמו** (לא JSON ידני, שיכול לסטות מהסכמה), ומפנה את השרת אליה עם
  `FAMILY_FINANCE_DATA_DIR`. ה־`.data` של המשפחה לא נפתח, לא נקרא ולא נכתב.
- **`SUPABASE_*` ריקים בסביבת השרת** — שגיאה ב־spec אינה יכולה להגיע למסד.
- **כל שם מתחיל ב־`E2E`**: `E2E משק בית בדיקה`, `E2E עובר ושב`, `E2E גמח ראשון`.
  בדיקה שמאמתת על `E2E גמח ראשון` אינה יכולה לעבור בשקט מול מלווה אמיתי.
- **מלווה לכל נושא**: לכל קובץ spec מלווה משלו, כדי ששניים לא יזיזו מספר שהשלישי
  מאמת עליו. שני מלווים (`E2E גמח אור`, `E2E גמח אור החיים`) לא נכתבים כלל, ויש
  בדיקה שמוודאת שהם עם אירוע אחד בלבד.
- **ניקוי**: `globalTeardown` עוצר את השרת ומוחק את התיקייה — **בהצלחה ובכשל**.
  מוחק בדיוק את התיקייה שהריצה יצרה. אין glob, אין "לנקות ריצות ישנות": ניקוי
  שמחפש הוא ניקוי שיכול למצוא את הדבר הלא נכון.

### החבילה החיה

- **שני משתמשים סינתטיים** ב־`auth.users`, בכתובות `e2e-<label>-<uuid>@example.test`
  (TLD שאינו יכול לקבל דואר). הסיסמה נוצרת בתהליך, נכנסת למסד רק כ־hash, ואינה
  מודפסת אף פעם.
- **שניים ולא אחד**: בידוד הוא טענה על משק בית שני שקיים ואינו נראה. עם משתמש
  אחד הבדיקה הייתה עוברת גם על מסד ריק.
- **הניקוי נמדד**: `globalTeardown` מוחק לפי מזהים — לעולם לא לפי תבנית — ואז
  **סופר**. אם נשארה שורה אחת, הריצה נכשלת. "הרצנו delete" אינה ראיה; אפס שורות
  כן.
- **שומרי ה־audit** מושהים בתוך טרנזקציה אחת בלבד, מופעלים לפני ה־commit,
  ו**מוכחים פעילים שוב** — אם ההוכחה נכשלת הטרנזקציה מתגלגלת אחורה.

## 4. פקודות

```bash
npm run e2e                 # כל החבילה המקומית (desktop + phone)
npm run e2e:smoke           # תת־קבוצת @smoke
npm run e2e -- e2e/specs/quick-update.spec.ts   # קובץ אחד
npm run e2e:install         # Chromium, לתוך הפרויקט
npm run e2e:live            # החבילה החיה — דורשת SUPABASE_DB_URL
npm run smoke:production    # השירות הפרוס, קריאה בלבד, בלי כניסה

# החבילה החיה מול השירות הפרוס — כניסה של אדם סינתטי לאתר האמיתי:
npm run e2e:live -- --live-origin=https://family-finance-web-l2gp.onrender.com
```

הדפדפן יורד ל־`.playwright-browsers/` **בתוך הפרויקט**. `tools/playwright.mjs`
כופה `PLAYWRIGHT_BROWSERS_PATH` בדיוק כמו ש־`tools/next.mjs` כופה כיבוי טלמטריה:
ברירת המחדל של Playwright היא cache ברמת המשתמש, וגבול הבטיחות ב־`CLAUDE.md`
אוסר לכתוב מחוץ לפרויקט.

**לפני הרצה צריך build.** שתי החבילות מריצות `next start` על `.next` וייכשלו
בקול אם הוא חסר.

## 5. שמות של סודות — לא ערכים

| שם | מי צריך | מאיפה |
|---|---|---|
| `SUPABASE_DB_URL` | `e2e:live` בלבד | `.env.integration.local` או CI secret |
| `NEXT_PUBLIC_SUPABASE_URL` | `e2e:live` | `apps/web/.env.local` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `e2e:live` | `apps/web/.env.local` |

`e2e` המקומית אינה צריכה אף אחד מהם. מפתח service-role אינו נקרא בשום מקום
בחבילות האלה.

`e2e:live` **נכשלת** כשחסר `SUPABASE_DB_URL`, ואינה מדלגת. ריצה ירוקה שלא בדקה
כלום היא בדיוק מה ש־`CLAUDE.md` אוסר.

## 6. מה רץ איפה

| | מקומי | CI | מול ייצור |
|---|:---:|:---:|:---:|
| `npm run verify` | ✅ | ✅ | — |
| `npm run e2e` (72 בדיקות) | ✅ | ✅ | — |
| `npm run e2e:live` (8 בדיקות) | ✅ | ❌ (אין secret) | — |
| `npm run integration` | ✅ | ❌ (אין secret) | — |
| `npm run validate:production-path` | ✅ | ❌ | — |
| `npm run smoke:production` | ✅ | ✅ (workflow נפרד) | ✅ |
| `e2e:live -- --live-origin=<prod>` | ✅ (ידני) | ❌ (אין secret) | ✅ |

**מה שאינו ב־CI, ולמה**: כל מה שדורש `SUPABASE_DB_URL`. הוספתו כ־secret היא
פעולה של הבעלים, והיא גם החלטה — connection string של owner ב־CI הוא משטח תקיפה.
עד שהיא תתקבל, הבדיקות האלה רצות מקומית ומתועדות כך ולא מוצגות כשער ירוק.

## 6א. הבדיקה המאומתת מול הייצור

`--live-origin` מפנה את אותן שמונה הבדיקות לשירות הפרוס במקום לשרת מקומי. זו
הבדיקה המאומתת מול ייצור שהמשימה מבקשת: אדם סינתטי נכנס **לאתר האמיתי**, מקים
משק בית משלו, רואה אותו ולא רואה את של השני, יוצא — ונמחק.

היא בטוחה מאותן סיבות שכל החבילה בטוחה: המשתמש נוצר כאן, אינו בעל דבר, אינו
מוזמן לשום מקום, ונמחק בסוף בטירדאון ש**סופר** ונכשל אם נשארה שורה. הוא אינו
יכול לכתוב למשק בית של מישהו אחר כי RLS אינו מרשה.

כשמופנה לשירות פרוס אין שרת מקומי להרים ואין צורך ב־build — רק המשתמשים
הסינתטיים נוצרים ונמחקים.

**אינה ב־CI**: היא דורשת `SUPABASE_DB_URL`. מה שצריך כדי להריץ אותה מ־CI רשום
בסעיף 5 ובדוח ה־UX.

## 7. Artefacts

trace ו־screenshot נשמרים **רק לכשל**, ל־`test-results/` שהיא git-ignored. ב־CI
הן נעלות כ־artifact רק ב־`failure()`. אין וידאו. שום artefact אינו מכיל נתוני
משפחה — הוא מכיל את משק הבית הסינתטי, שכל שם בו מתחיל ב־`E2E`.

## 8. מגבלות, במפורש

- **`smoke:production` אינו אומר איזה commit חי.** `/api/health` אינו מפרסם גרסה,
  ולכן טענה כזאת הייתה מומצאת. הוא מאמת תכונות שנכונות לכל גרסה פרוסה.
- **`workflow_run` + השהיה אינם ערובה** שהפריסה הסתיימה. זו הערכה סבירה, לא
  סנכרון. הפתרון האמיתי הוא מזהה build ב־health — רשום כ־P2.
- **התוכנית החינמית של Render נרדמת.** הבדיקה מנסה שלוש פעמים כדי להעיר; שירות
  שבאמת מושבת נכשל בכל השלוש.
- **מה שממומש (mock) בכל החבילות**: יכולת דפדפן אחת — היעדר `SpeechRecognition`,
  כדי לוודא שההקלדה לבדה מספיקה. שום דבר כספי אינו מומש, ושום רשת אינה מיושרת.
