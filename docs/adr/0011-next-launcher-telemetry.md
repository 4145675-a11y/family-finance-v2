# ADR-0011: launcher מקומי ל־Next שאוכף חסימת טלמטריה בכל פלטפורמה

- **Status**: Accepted
- **Date**: 2026-08-16
- **Milestone**: 1
- **Supersedes**: [ADR-0010](0010-framework-telemetry-disabled.md) (סעיף ההרצה המקומית בלבד)
- **Requirement IDs**: —

## הקשר

`ADR-0010` הגדיר `NEXT_TELEMETRY_DISABLED=1` ברמת ה־workflow ב־CI, אך השאיר את ההרצה המקומית כ**המלצה מתועדת**: "מומלץ לייצא את המשתנה".

הפער בגישה הזו הוא לא תיאורטי. `npm run dev` על מכונת מפתח הוא הנתיב הנפוץ ביותר, והוא בדיוק הנתיב שלא כוסה. הגנה שתלויה בכך שמישהו יזכור לייצא משתנה אינה הגנה, והיא נכשלת בשקט — אין שום סימן לכך שהיא לא פעלה.

האילוצים לא השתנו:

- `next telemetry disable` כותב קובץ ברמת המשתמש, מחוץ לשורש הפרויקט — אסור לפי גבול הבטיחות ב־`CLAUDE.md`.
- npm scripts אינם יכולים להגדיר משתנה סביבה בצורה נייטרלית לפלטפורמה (`VAR=1 cmd` הוא תחביר POSIX ונשבר ב־cmd.exe של Windows).
- `.env` מחויב היה דורש חריגה ב־`.gitignore` שמכשירה קובץ סביבה במאגר.

## החלטה

1. **`tools/next.mjs`** הוא הדרך היחידה שבה הפרויקט מפעיל את Next. הוא מייצר את הסביבה עם `NEXT_TELEMETRY_DISABLED=1` ומריץ את ה־CLI כתהליך בן.
2. `apps/web/package.json` מריץ `dev`, `build` ו־`start` דרך ה־launcher בלבד.
3. **`tools/next-telemetry.test.mjs`** מונע רגרסיה: הוא סורק כל `package.json` בפרויקט ונכשל אם script כלשהו מריץ `next dev|build|start|lint|telemetry` ישירות.
4. הגדרת ה־env ב־CI **נשארת**, כהגנה שנייה שאינה תלויה בקוד הפרויקט.
5. `next telemetry disable` לא מורצת, ואף קובץ ברמת המשתמש אינו נקרא, נכתב או נמחק.

## פרטי מימוש

- אפס תלויות — Node built-ins בלבד, כמו שאר `tools/`.
- ה־CLI מורץ כ־`node <path-to-next-bin>` ולא דרך ה־shim של המערכת, כדי לעקוף הבדלי `.cmd`/`.ps1` בין Windows ל־POSIX.
- `nextEnv()` **דורס** ערך שהגיע בירושה: גם `NEXT_TELEMETRY_DISABLED=0` בסביבה החיצונית מתורגם ל־`1`. חסימה שאפשר לבטל בטעות מבחוץ אינה חסימה.
- קוד היציאה של Next מוחזר כמו שהוא, כך שהתנהגות השערים לא משתנה.

## חלופות שנשקלו

| חלופה | מדוע נדחתה |
|---|---|
| `cross-env` | תלות שלמה עבור משתנה יחיד; ADR-0010 כבר דחה, וזה עדיין נכון כשקיימת חלופה של 40 שורות |
| `.env` מחויב | חריגה ב־`.gitignore` שמכשירה קובץ סביבה במאגר — סיכון עתידי לסוד |
| `next telemetry disable` | כותב מחוץ לשורש הפרויקט |
| להשאיר המלצה מתועדת (המצב הקודם) | נכשל בשקט; אינו מכסה `npm run dev` |
| launcher + בדיקת רגרסיה (נבחר) | אוכף בכל פלטפורמה, אפס תלויות, והעקיפה נחסמת בבדיקה |

## מה נותר פתוח

מפתח שמריץ `npx next dev` ידנית בטרמינל שלו עוקף את ה־launcher. זה מחוץ לשליטת המאגר. כל נתיב ש**הפרויקט** מגדיר — מכוסה.

## השלכות

- חיוביות: כל פקודת Next של הפרויקט חוסמת טלמטריה, בכל מערכת הפעלה; עקיפה מפילה בדיקה עם הודעה שמסבירה מה לעשות.
- שליליות: שכבת עקיפה דקה בין npm ל־Next; מי שקורא את `package.json` צריך צעד אחד נוסף כדי לראות מה רץ.
- לאימות: 25 בדיקות ב־`tools/next-telemetry.test.mjs`; אומת שלילית — החזרת `"start": "next start"` הפילה את החבילה עם exit 1.

## תנאי ביטול

אם Next יאפשר השבתת טלמטריה דרך `next.config.ts`, ה־launcher יוסר וההגדרה תעבור לקונפיגורציה. בדיקת הרגרסיה תתעדכן בהתאם ולא תימחק.
