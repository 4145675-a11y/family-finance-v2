# ADR-0004: מרשם דרישות נפרד במקום עריכת מסמכי הסמכות

- **Status**: Accepted
- **Date**: 2026-08-15
- **Milestone**: 0
- **Requirement IDs**: כל המזהים

## הקשר

בדיקת העקביות שנדרשה ב־Milestone 0 מצאה שני פערים אמיתיים בין מסמכי הסמכות למטריצה:

1. שמונה מזהים מוגדרים במסמכי מקור ואינם ממופים במטריצה: `PROD-KPI-001` עד `PROD-KPI-006`, `UX-A11Y-001`, `UX-STATE-001`.
2. שישה מזהים ממופים במטריצה בלי שתווית המזהה מופיעה בגוף מסמך המקור: `SEC-RLS-001`, `OFF-SYNC-001`, `IMP-DRAFT-001`, `AI-TOOL-001`, `FIN-ROLL-001`, `UX-DEBT-002`. הטקסט הדרישתי עצמו קיים בכל אחד מהמקרים; מה שחסר הוא התווית.

בנוסף, `04`, `05`, `07`, `08` ו־`11` נושאים דרישות מחייבות בלי אף תווית מזהה.

הפתרון המתבקש — להזריק תוויות מזהים לתוך מסמכי החוקה — משנה טקסט סמכותי בשלב bootstrap, וזו פעולה בעלת סיכון גבוה: היא מטשטשת את הגבול בין "מה שנקבע" לבין "מה שקלוד הוסיף".

## החלטה

1. נוצר `docs/REQUIREMENTS.md` כמרשם מזהים. הוא **אינו** סמכות עסקית; הסמכות נשארת במסמכי החוקה לפי סדר ה־README. המרשם מצמיד לכל מזהה: ניסוח קנוני, מסמך וסעיף מקור, milestone אחראי וסטטוס.
2. מסמכי הסמכות `01`–`09` ו־`11` **לא שונו**. לא נוסף, לא נמחק ולא נוסח מחדש אף טקסט דרישתי.
3. `10-TRACEABILITY-MATRIX.md` הורחב בשמונה השורות החסרות בלבד. המסמך עצמו מורה "יש להרחיב בכל milestone", ולכן ההרחבה היא שימוש מיועד ולא שינוי סמכות.
4. Milestone 0 **לא המציא** דרישות חדשות. כל מזהה במרשם מצביע על טקסט שכבר קיים.
5. שאר הדרישות ב־`04`, `05`, `07`, `08`, `11` יקבלו מזהים ב־milestone שמממש אותן. הפער רשום במפורש ב־`docs/REQUIREMENTS.md` וב־`MILESTONE_STATUS.md`.
6. העקביות נאכפת על ידי `npm run check:traceability`, ולא על ידי משמעת אנושית.

## חלופות שנשקלו

| חלופה | יתרון | חיסרון | מדוע נדחתה |
|---|---|---|---|
| להזריק תוויות לכל מסמכי הסמכות | מקור יחיד | קלוד משכתב חוקה בשלב bootstrap; קשה לביקורת | סיכון גבוה מדי לתועלת |
| להשאיר את הפער ולדווח בלבד | אפס שינוי | הדרישה המפורשת של M0 היא מיפוי, לא רק דיווח | לא ממלא את ה־scope |
| מרשם נפרד + שער אכיפה (נבחר) | מזהים ומיפוי מלאים; חוקה לא נגועה; drift נחסם אוטומטית | שכבת תיעוד נוספת לתחזוקה | — |

## השלכות

- חיוביות: 23 מזהים רשומים וממופים; שער אוטומטי מונע רגרסיה; מסמכי הסמכות נשארים כפי שנמסרו.
- שליליות: שני מקומות לעדכן כשנוספת דרישה (מרשם + מטריצה). השער מוודא שלא שוכחים.
- לאימות: `npm run check:traceability` — נבדק גם חיובית (23/23 מתואמים) וגם שלילית (מזהה לא רשום במטריצה מפיל את השער עם exit 1).

## תנאי ביטול

אם בעל המוצר יורה להטמיע את התוויות בתוך מסמכי הסמכות, המרשם יהפוך לאינדקס בלבד וה־ADR יוחלף.
