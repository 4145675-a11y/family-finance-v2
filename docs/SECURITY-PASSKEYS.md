# כניסה מאובטחת עם Windows Hello

מדריך למי שמפעיל את האפליקציה, ולמי שצריך לדעת בדיוק ממה היא מגנה.

## הכתובת

**כניסה עובדת רק ב־`http://localhost:3100`.**

בכתובת `http://127.0.0.1:3100` הדפדפן מסרב לפתוח מפתח כניסה. הסיבה אינה קשורה לאבטחת האפליקציה: מזהה האתר ב־WebAuthn חייב להיות שם מתחם, וכתובת IP אינה שם מתחם. כרומיום מחזיר `SecurityError: This is an invalid domain` עוד לפני שהוא פונה ל־Windows Hello.

שתי הכתובות מגיעות לאותו שרת ולאותו מחשב. השרת מאזין ל־`127.0.0.1` בלבד ואינו נפתח לרשת. אבל לדפדפן אלה שני אתרים שונים: עוגייה שנקבעה באחד אינה נשלחת לשני, ומפתח שהוגדר באחד אינו עובד בשני.

המסכים אומרים את זה כשמגיעים אליהם מהכתובת הלא נכונה, ומקשרים לנכונה.

| | |
|---|---|
| מקור נתמך | `http://localhost:3100` |
| מזהה אתר (RP ID) | `localhost` |
| שינוי | `FAMILY_FINANCE_AUTH_ORIGIN` |

## מה נשמר, ומה לא

**טביעת אצבע לא נשמרת, לא מתקבלת ולא נשלחת. אף פעם.** הבדיקה הביומטרית מתרחשת בתוך Windows Hello ובתוך המכשיר. מה שהאפליקציה מקבלת בסוף הטקס הוא חתימה.

נשמר ב־`.data/auth.json`:

- מזהה המפתח ומפתח ציבורי — מספר שאפשר לבדוק איתו חתימה ואי אפשר לחתום איתו;
- מונה חתימות, כדי לזהות מפתח שהועתק;
- שם שנתתם למפתח, וחותמות זמן;
- יומן של כניסות, ניסיונות שנכשלו ושינויי הגדרות — עם קוד סיבה קצר, בלי חתימות ובלי תוכן.

אין בסכימה שדה שיכול להחזיק תבנית ביומטרית או תמונה.

הקובץ נפרד ממסמך משק הבית בכוונה (ADR-0028): גיבוי נועד לנסוע, ומפתח כניסה קשור למכשיר הזה. שחזור גיבוי אינו יכול להסיר את המפתח שלכם ואינו יכול להתקין מפתח של מישהו אחר.

## ממה זה מגן

- מישהו שמתיישב מול המחשב הפתוח ומנסה לפתוח את האפליקציה.
- דף אחר בדפדפן שמנסה לפנות לאפליקציה — הוא אינו יכול לחתום בשמכם, והמקור נבדק במלואו כולל הפורט.
- חזרה על כניסה שהוקלטה: כל אתגר תקף פעם אחת בלבד ופג אחרי שתי דקות.
- מפתח שהועתק: מונה החתימות חייב להתקדם, כשהמאמת מנהל מונה.
- פעולה רגישה במחשב שנשאר פתוח: שחזור, ייצוא ושינוי מפתחות דורשים Windows Hello מחדש בחמש הדקות האחרונות.

## ממה זה לא מגן

- **הקבצים אינם מוצפנים.** הנעילה שומרת על המסכים, לא על הדיסק. מי שיש לו גישה לתיקייה קורא את `household.json` בלי לעבור בכלל דרך האפליקציה.
- **הרשאת מנהל במחשב עוקפת הכול**, כולל את הקבצים האלה.
- **גיבוי שהוצאתם לקובץ אינו מוגן בנעילה הזו.** שמרו אותו במקום בטוח.
- **אין אימות attestation.** האפליקציה אינה טוענת דבר על דגם המאמת. עבור אפליקציה ביתית זו העסקה הנכונה — attestation מעיד על יצרן ה־TPM ולא על מי שיושב מול המקלדת.
- **העוגייה אינה `secure`**, כי המקור הוא `http`. עוגייה מאובטחת פשוט לא הייתה נשלחת. התעבורה אינה יוצאת מהמחשב.

## מתי ננעל מחדש

| | ברירת מחדל | שינוי |
|---|---|---|
| חוסר פעילות | 15 דקות | מסך האבטחה |
| תקרה מוחלטת | 12 שעות | קבוע |

התקרה המוחלטת קיימת כי חוסר פעילות לבדו היה מאפשר ללשונית פתוחה שנוגעים בה מדי פעם להישאר פתוחה לנצח.

## אם אין גישה למפתח

**הדרך הבטוחה היא מפתח שני שהוגדר מראש** — במחשב אחר, או מפתח אבטחה פיזי. אפשר להגדיר עד עשרה.

אם אין מפתח שני:

```
npm run auth:reset
```

מהמחשב הזה, בתיקיית הפרויקט. הפקודה מסירה את המפתחות ואת הסשנים, כותבת רישום איפוס ליומן, **ואינה נוגעת בנתונים הכספיים**.

אין קוד עוקף ואין סיסמה חלופית, ולא במקרה: כל אחד מהם היה דרך כניסה שנייה חלשה מהראשונה. הפקודה דורשת בדיוק את הגישה שממילא מאפשרת לקרוא את `.data/household.json` ישירות, ולכן היא אינה מוותרת על שום דבר שהנעילה שמרה עליו.

עם `NODE_ENV=production` היא מסרבת לרוץ אלא אם נמסר `--i-am-at-the-machine`. היא אינה מסלול HTTP ואין דרך להגיע אליה מהדפדפן.

## אם אין Windows Hello

המסך אומר זאת ומציע את הצעד הבא — הגדרת Windows Hello בהגדרות Windows, תחת חשבונות → אפשרויות כניסה. עד אז האפליקציה פועלת בלי נעילה, וזה נאמר במפורש ולא מוסתר.

## מה נבדק אוטומטית ומה לא

**נבדק (112 בדיקות):** רישום ואימות בשלושה אלגוריתמים עם חתימות אמיתיות; מקור שגוי; פורט שגוי; `127.0.0.1` במקום `localhost`; RP ID שגוי; היעדר אימות משתמש; היעדר נוכחות; רישום שהופעל כניסה ולהפך; אתגר שפג; אתגר שנוצל; אתגר של סשן אחר; מפתח לא מוכר; חתימה ממפתח אחר; מונה שלא התקדם; קלט פגום; פקיעת סשן; דרישת אישור חוזר.

**לא נבדק אוטומטית:** טקס Windows Hello אמיתי. הדפדפן דורש חלון במיקוד ומחזיר `NotAllowedError: the page does not have focus` תחת אוטומציה. זו בדיקה שרק אדם מול המחשב יכול לבצע, והיא הראשונה ברשימת הבדיקה הידנית.
