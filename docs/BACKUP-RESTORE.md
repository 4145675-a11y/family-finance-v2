# BACKUP AND RESTORE

איפה הנתונים נמצאים, איך לוקחים מהם עותק, ואיך מחזירים אותו.

מקורות: `11-OPERATIONS.md`, `05-ARCHITECTURE-DATA.md` § גבולות. ההחלטה: `ADR-0024`.

## איפה הנתונים

```
.data/
  household.json          ← כל האמת של משק הבית. קובץ אחד.
  household.json.writing  ← קיים רק בזמן כתיבה. rename מעליו הוא האטומיות.
  history/                ← עשרים המסמכים הקודמים, אחרי כל שינוי
  uploads/                ← קבצים שהועלו וטרם הוכרעו, לפי מזהה שנוצר
  backups/                ← גיבויים שביקשתם
```

התיקייה נמצאת בשורש הפרויקט והיא ב־`.gitignore`. שום דבר ממנה אינו נכנס ל־git, אינו נשלח
לשום מקום, ואינו נקרא בידי אף גורם חיצוני.

`FAMILY_FINANCE_DATA_DIR` מפנה את החנות למקום אחר. הוא קיים כדי שבדיקות ושערים לא יכתבו
מעל משק הבית של המפתח, ואינו נגזר לעולם ממשהו שבקשה נושאת.

## מה יש בגיבוי

חשבונות, יתרות מאושרות, תנועות, פריטים צפויים, חובות ואירועי חוב, גלגולים, תקציבים,
משימות, היסטוריית היבוא על כל ההצעות שלה, ההגדרות, ורישום הפעולות המלא.

**אין בגיבוי סיסמאות, מפתחות או טוקנים — כי אין כאלה במערכת.** זו תכונה לשמור עליה, לא
מקרה: `packages/local-store/src/backup.test.ts` סורק את הטקסט ונכשל אם מילה כזו מופיעה.

## מבנה הקובץ

```json
{
  "kind": "family-finance-backup",
  "envelopeVersion": 1,
  "createdAt": "...",
  "producedBy": "family-finance-control",
  "documentFormatVersion": 1,
  "checksum": "<sha256 של הנתונים>",
  "summary": { "...": "מה יש בפנים" },
  "document": { "...": "הנתונים" }
}
```

ה־checksum נלקח על **סריאליזציה קנונית** של הנתונים — מפתחות ממוינים בכל עומק — כי מסמך
שעבר ולידציה חוזר עם המפתחות בסדר של הסכמה ולא בסדר של הקובץ. checksum על סריאליזציה רגילה
היה נכשל על גיבוי תקין לחלוטין.

ה־`summary` נמצא **מחוץ** ל־checksum, ולכן הוא מתויג ולא ראיה: מה שמסך השחזור מציג מחושב
מהנתונים עצמם. `backup.test.ts` מוכיח שגיבוי עם summary משוקר עדיין מדווח את האמת.

## ליצור גיבוי

מסך `עוד → גיבוי ושחזור → ליצור גיבוי עכשיו`. הקובץ נשמר ב־`.data/backups/` בשם שנושא
תאריך ושעה ואינו נושא דבר על המשפחה. משם אפשר להעתיק אותו לכונן חיצוני.

## לשחזר

שני שלבים, ולא אפשר לאחד אותם:

1. **לבדוק את הקובץ.** נקרא, מאומת, ומדווח מה יש בפנים ומה יש כאן עכשיו. **שום דבר לא
   מוחלף בשלב הזה.**
2. **לשחזר.** מופיע רק אחרי שהבדיקה הצליחה, ודורש להקליד את המילה `שחזור`. הקובץ מאומת
   שוב בשרת — אלו שתי בקשות נפרדות, וערך שעבר דרך דפדפן אינו ראיה בחזרתו.

המצב הקודם נשמר ב־`history/`.

## מה נדחה, ולמה בשמו

| מצב | ההודעה |
|---|---|
| לא JSON | הקובץ אינו קריא; ייתכן שההורדה נקטעה |
| JSON שאינו גיבוי | לא נוצר על ידי האפליקציה |
| checksum לא תואם | הקובץ השתנה מאז שנוצר |
| envelope חדש יותר | נוצר בגרסה חדשה יותר של האפליקציה |
| פורמט נתונים לא מוכר | הגרסה הזו לא יודעת לקרוא אותו |
| נתונים לא תקינים | התוכן אינו עומד בסכמה |

שש הודעות ולא אחת. "השחזור נכשל" לא היה אומר למשפחה איזו מהן קרתה, ולכל אחת יש תשובה אחרת.

## מה עוד לא קיים

- **אין הצפנה במנוחה.** הקובץ מוגן בהרשאות מערכת ההפעלה בלבד. מי שיש לו גישה למשתמש שלכם
  יכול לקרוא אותו. זה נאמר במסך הפרטיות.
- **אין גיבוי אוטומטי מתוזמן.** גיבוי נוצר כשמבקשים.
- **אין סנכרון בין מכשירים.** נדרש שרת משותף — ראה `docs/EXTERNAL-INTEGRATIONS.md`.
- **אין איפוס הרס.** לא נבנה כאן במכוון.
